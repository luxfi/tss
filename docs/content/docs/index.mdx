# Lux TSS - Threshold Signature Schemes

## Overview

Lux TSS (Threshold Signature Schemes) is a production-ready implementation of multi-party threshold cryptographic protocols for ECDSA and EdDSA. This library enables secure distributed key management where multiple parties collaborate to generate signatures without any single party having access to the complete private key.

## What is Threshold Signature Scheme?

A threshold signature scheme is a cryptographic protocol that allows a group of parties to jointly produce signatures. In a (t,n)-threshold scheme:
- **n** = total number of participants
- **t** = threshold number (minimum parties needed to sign)
- Any **t+1** parties can collaborate to produce a valid signature
- Fewer than **t+1** parties cannot generate a signature or recover the private key

## Core Protocols

### 1. Distributed Key Generation (DKG)
Generate key shares without any party knowing the complete private key:
- Each party generates partial key shares
- Verifiable secret sharing ensures share validity
- Commitment schemes prevent cheating
- Final public key derived from all contributions

### 2. Threshold Signing
Collaboratively generate signatures using key shares:
- Pre-signing phase for efficiency
- MPC (Multi-Party Computation) for signature generation
- No reconstruction of private key during signing
- Signature indistinguishable from single-party signature

### 3. Key Resharing
Dynamically change the participant group while preserving the key:
- Add or remove parties from the signing group
- Change the threshold value (t)
- Refresh shares for proactive security
- Maintain same public key throughout

### Protocol Flow

#### Key Generation Flow
```
Round 1: Share Generation
├── Generate ui (partial key)
├── Compute VSS shares
├── Create Paillier keys
└── Broadcast commitments

Round 2: Share Distribution
├── Send VSS shares to parties
├── Generate DLN proofs
└── Broadcast Paillier public keys

Round 3: Share Verification
├── Verify VSS shares
├── Verify DLN proofs
├── Compute xi (key share)
└── Store save data
```

#### Signing Flow
```
Round 1: Pre-signing
├── Generate ki, γi
├── Compute Ri = ki·G
└── Broadcast commitments

Round 2-4: MTA Protocol
├── MTA for ki·γj
├── MTA for ki·wj
└── Verify MTA proofs

Round 5-7: Signature Generation
├── Compute R = Σ(Ri)
├── Compute si shares
├── Verify signature shares
└── Output (r,s) signature
```

## Security Considerations

### Threat Model
- **Honest Majority**: Protocol secure with up to t malicious parties
- **Network Adversary**: Resilient to message delays and reordering
- **Adaptive Security**: Security maintained even if adversary corrupts parties adaptively
- **Concurrent Sessions**: Safe to run multiple signing sessions simultaneously

### Implementation Security
- **Secure Random Generation**: Uses crypto/rand for all randomness
- **Side-Channel Protection**: Constant-time bigint operations
- **Memory Safety**: Go's memory management prevents common vulnerabilities
- **Input Validation**: Comprehensive validation of all protocol messages

### Best Practices
1. **Secure Storage**: Encrypt key shares at rest
2. **Network Security**: Use TLS for party communication
3. **Access Control**: Implement authentication for party participation
4. **Audit Logging**: Log all protocol operations for forensics
5. **Key Rotation**: Regularly refresh shares using resharing protocol

## Quick Start

### Installation
```bash
go get -u github.com/luxfi/tss/v2
```

### Basic Usage
```go
import (
    "github.com/luxfi/tss/v2"
    "github.com/luxfi/tss/v2/ecdsa/keygen"
    "github.com/luxfi/tss/v2/ecdsa/signing"
)

// Initialize parameters
curve := tss.S256() // or tss.Edwards() for EdDSA
parties := tss.SortPartyIDs(getPartyIDs())
ctx := tss.NewPeerContext(parties)
params := tss.NewParameters(curve, ctx, thisParty, n, t)

// Run key generation
party := keygen.NewLocalParty(params, outCh, endCh)
go party.Start()

// Handle messages and get final key shares
// ... (see API reference for details)
```
